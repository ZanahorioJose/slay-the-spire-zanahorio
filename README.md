# 杀戮尖塔 DIY（Slay the Spire DIY）

网页端、数据驱动的杀戮尖塔式卡牌构筑游戏。核心目标：玩家可以自由 DIY 卡牌、怪物、遗物、事件，并通过数据文件夹随身携带。

## 运行方式

- 双击 scripts/start_game.bat，或命令行执行 `npm run dev`，浏览器访问 http://localhost:5173
- 生产构建：`npm run build`（产物在 dist/，data/ 会自动复制到 dist/data/）
- 在另一台电脑上初始化游玩：见 `GETTING_STARTED.md`

## 技术栈

Vite + TypeScript + 原生 DOM/CSS，无后端、无游戏引擎。

## 已完成功能

1. **战斗系统**：回合循环、抽牌/弃牌/消耗堆/**移除池**、能量、格挡、状态效果（力量、敏捷、易伤、虚弱、中毒、脆弱、荆棘、仪式、金属化、虚无、人工制品）、敌人意图（循环/随机两种模式）、多敌人战斗。敌人防御获得的格挡会保留到你的回合并正确吸收伤害，下次行动前才清空。**能力牌打出后进移除池（本场战斗暂时移除，下一场照常可用），与消耗堆分离**。
2. **爬塔流程**：3 层地图（**先古事件**/战斗/精英/事件/商店/篝火/宝箱/Boss），**每层第一个节点是先古事件**：先回血（回复缺失生命值的 X%，默认 100），再随机获得一件先古遗物。节点选择与可达性判断，**地图以 SVG 曲线画出完整路径网络，当前节点出发的可走路线金色高亮**，Boss 通关进入下一层，3 层通关。
3. **构筑系统**：战斗胜利 3 选 1 卡牌奖励（**精英额外随机给一件遗物，Boss 胜利也有卡牌奖励**）、商店购买/移除（**移除卡牌按实例用卡图选择，带确认弹窗**）、篝火休息/锻造（**升级卡带确认弹窗**）、随机事件（含触发战斗、花金币选项；**获得遗物有 toast 提示**）。
4. **卡牌实例 ID 架构**（重要）：
   - 游戏外（卡组、数据文件、编辑器）：使用静态卡牌 id，如 strike、heavy_blow
   - 游戏内：战斗开始时每张牌实例化，分配战斗专属 uid（c1、c2...），牌堆/手牌/弃牌堆存 uid，通过 uid→cardId 映射解析
   - 好处：同名牌可区分；战斗中生成的新卡有独立实例；未来可在实例上挂附加效果（遗物/怪物赋予的临时效果）
   - 相关类型：CardInstance（core/types.ts），Combat 内 instances 映射
5. **升级系统**：篝火锻造弹出卡片选择面板，显示「当前卡面 ➜ 升级后卡面」对比；**每次升级只升选中的那一张（按牌组实例），同名多张卡分别展示、互不影响**；事件随机升级也只升一张。升级牌用 `${id}+` 表示，**一律**由基础卡在构建数据库时动态派生（`upgrade` 字段只存覆盖项：费用/描述/效果/消耗），改基础卡数值会自动同步到升级版；编辑器里升级效果支持「继承基础效果 / 自定义升级效果」两种模式切换。**旧格式的显式 `<id>+` 卡数据会在加载时自动清理**，升级卡不允许独立存储。
6. **DIY 编辑器**（主菜单 → 编辑）：
   - 卡牌 / 怪物 / 遗物 / 事件 / **先古**五个页签，可视化表单编辑，行式效果编辑器；
     卡牌与遗物支持**版本/拓展包字段**（如「基础版」「DLC1」）
   - 「全局设置」页签：初始生命、初始金币、每回合抽牌数、每回合能量、起始牌组、
     **先古回血比例、先古角色**
   - 数据分两层（见下），支持导出/导入 JSON；同名 id 覆盖内置数据，值为 null 表示删除内置条目
   - 事件选项支持 goldCost（花金币）、fightEnemy（触发战斗）、addCards、addRelic、
     **addRelicPool（随机遗物池）**、removeCards、loseMaxHp、upgradeRandomCard
7. **UI 布局**：战斗中角色与怪物**水平居中、左右对峙**（角色在左、怪物在右，怪物横向排开），底部手牌、中间日志。地图页有「卡组」「遗物」查看按钮，角色面板与怪物面板位置可用 CSS 变量 `--player-offset-x/y`、`--enemy-offset-x/y` 微调。编辑卡牌时有**基础卡 ➜ 升级卡实时左右对比**。**全部卡牌为磨砂玻璃材质**（半透明玻璃体 + 模糊 + 高光带，颜色随卡牌类型色）。
8. **快捷键**（战斗中）：`A` 抽牌堆、`S` 弃牌堆、`D` 牌库（卡组）——按一次打开、再按一次关闭；`F` 任意游戏界面查看地图（可切换开关）；`E` 结束回合；`ESC` 取消卡牌选中；数字 `1-0` 依次选择手牌从左到右第 1-10 张。
   - **防误触出牌**：所有卡牌都采用「先选中、再确认」——单体目标卡选中后点敌人打出；无目标卡（技能/全体/随机）选中后再点一次打出。数字键只负责选中，不会直接出牌。
9. **数据文件夹（data/）**：DIY 正式数据写入 data/*.json（cards/enemies/relics/events/settings.json），拷走整个项目文件夹即可随身携带。三档数据源自动降级：
   - ① 绑定的 data 文件夹（File System Access API，主菜单或编辑器里点「绑定 data 文件夹」，句柄存 IndexedDB）
   - ② 本地服务器自动读取 `./data/*.json`（npm run dev / 静态托管）
   - ③ localStorage 兜底（file:// 双击打开、未绑定时）
   - 旧的 localStorage DIY 数据（slay-the-spire-diy-v1）会自动迁移到正式层
10. **存档系统**：游戏进程自动存档到 data/save.json（绑定文件夹时）或 localStorage（兜底）；主菜单检测到存档显示「继续上次（第 X 层 · 生命 x/y）」；战斗中不存快照，恢复到战斗前的节点状态；失败/通关自动清除存档。
11. **数值调整分层**：
    - 永久层 = data/*.json（版本/补丁级改动，编辑器「写入正式数据」固化）
    - 临时层 = localStorage 调试覆盖（编辑器「临时微调」，立即生效，可一键「清空临时调整」）
    - 列表条目带来源标记：金色边框 = 正式数据，绿色边框 = 临时调整；删除也分「删除（临时）/删除（正式）」
12. **测试房间**（主菜单 → 🧪 测试房间）：设置初始生命/金币后选择任意事件，立即以该状态进入事件测试选项逻辑；事件结束后自动回到测试房间，方便连续测试。

## 战斗事件触发顺序（严格串行，禁止"同时结算"）

游戏里**不存在任何同时发生的事件**：所有看似同时的效果都被拆成固定先后顺序。遗物触发时机可自定义：战斗开始时 / 回合开始时 / 回合结束时 / 打出一张牌时 / 造成伤害时 / 获得格挡时 / 战斗结束时。

1. **战斗开始（combatStart）**：洗牌 → 按获得顺序触发遗物 → 开始第 1 回合
2. **回合开始（turnStart）**：清除格挡 → 重置能量（含遗物加成）→ 中毒结算 → 抽牌（含遗物加成）→ 按获得顺序触发遗物
3. **打出卡牌（cardPlayed）**：支付费用 → 效果数组**逐个按顺序结算**（同一张卡内的多个效果也严格有序）→ 卡牌进弃牌/消耗堆（能力牌进**移除池**）→ 按获得顺序触发遗物 → 战斗结束判定
   - 造成伤害：每次命中 = 伤害 → 荆棘反伤 → 触发「造成伤害时」遗物（遗物效果产生的伤害**不会**再次触发，防递归）
   - 获得格挡：计算（敏捷加成/脆弱衰减）→ 获得 → 触发「获得格挡时」遗物（同样防递归）
4. **回合结束（turnEnd）**：弃手牌 → 负面状态衰减 → 按获得顺序触发遗物 → 回合结束状态效果（仪式 → 金属化）
5. **敌人回合**：按入场顺序逐个行动（毒结算 → 行动 → 状态衰减 → 清格挡），玩家死亡立即判负
6. **战斗结束（battleEnd）**：胜利时按获得顺序触发一次，然后结算奖励；失败直接结束

多个遗物在同一时机触发时，一律按**获得顺序**执行。

## 核心文件

- src/core/types.ts —— 所有数据模型与类型
- src/core/combat.ts —— 战斗状态机（效果结算、意图、回合）
- src/core/game.ts —— 游戏会话（开局、地图、事件、奖励、全局设置、fromRun 存档恢复）
- src/core/map.ts —— 地图生成
- src/data/*.ts —— 内置数据（卡牌/怪物/遗物/事件/先古角色）
- src/data/store.ts —— 数据源抽象（data/ 目录、HTTP、localStorage 三档 + 正式/临时分层 + 存档读写）
- src/data/index.ts —— 数据合并（内置 → 正式层 → 临时层）
- src/ui/battleView2.ts —— 战斗界面
- src/ui/ancientView.ts —— 先古事件界面
- src/ui/editorView.ts —— DIY 编辑器（分层保存）
- src/ui/upgradePicker.ts —— 升级卡牌选择面板
- src/ui/testRoomView.ts —— 测试房间（指定事件 + 自定义初始状态）
- scripts/core_test.ts —— 核心逻辑测试（esbuild 打包后 node 运行）
- scripts/copy-data.mjs —— 构建时把 data/ 复制到 dist/data/

## 环境说明

- 环境要求与初始化步骤见 `GETTING_STARTED.md`（Node >= 18 / 推荐 Chrome/Edge）
- 数据默认存 localStorage（按 localhost 域名）；在编辑器或主菜单绑定 data 文件夹后，正式数据与存档写入 data/ 目录，实现跨电脑随身携带
- 项目级 `.codex/config.toml` 是 Codex 沙箱写权限配置，指向本机路径、不入库；换机器需自行更新
