# 开发说明（DEVELOPMENT）

> 本文档面向开发者：技术栈、功能清单、架构细节与核心文件。
> 面向玩家的游戏介绍与展示见根目录 `README.md`；新设备初始化见 `GETTING_STARTED.md`；版本演进见 `CHANGELOG.md`。

## 技术栈

Vite + TypeScript + 原生 DOM/CSS，无后端、无游戏引擎。

## 常用命令

- 双击 `scripts/start_game.bat`，或命令行执行 `npm run dev`，浏览器访问 http://localhost:5173
- 生产构建：`npm run build`（产物在 dist/，data/ 会自动复制到 dist/data/）
- 类型检查：`npx tsc --noEmit`
- 核心逻辑测试：`npx esbuild scripts/core_test.ts --bundle --platform=node --format=esm --outfile=scripts/core_test.mjs && node scripts/core_test.mjs`

## 已完成功能

1. **战斗系统**：回合循环、抽牌/弃牌/消耗堆/**移除池**、能量、格挡、状态效果（力量、敏捷、易伤、虚弱、中毒、脆弱、荆棘、仪式、金属化、虚无、人工制品、**星辉、灵魂涌动、灾厄**）、敌人意图（循环/随机两种模式）、多敌人战斗。敌人防御获得的格挡会保留到你的回合并正确吸收伤害，下次行动前才清空。**能力牌打出后进移除池（本场战斗暂时移除，下一场照常可用），与消耗堆分离**。**荆棘双向反伤**：怪打带荆棘的你自损、你打带荆棘的怪受伤。**药水**：背包上限 3 瓶，战斗中使用。
2. **角色系统**：主菜单可选 **5 个 STS2 初始角色**——铁甲战士（80 血/燃烧之血）、静默猎手（70 血/蛇之戒）、储君（75 血/神圣权柄，**星辰**体系）、亡灵契约师（66 血/绑定魂匣，**灵魂+召唤+灾厄**体系）、故障机器人（75 血/破损核心，**宝珠**体系）。每个角色有专属起始牌组与初始遗物；**卡牌奖励与商店只出当前角色专属卡 + 无色卡**。
3. **爬塔流程**：3 幕地图（**先古事件**/战斗/精英/事件/商店/篝火/宝箱/Boss），
   **每幕层数固定、每层固定 3 个房间**（第 1 幕 17 层 / 第 2 幕 16 层 / 第 3 幕 15 层，
   含首尾先古与 Boss 层），结构对齐《杀戮尖塔 2》：
   先古后的首层必为普通战斗；每幕中部固定宝箱层（第 1 幕第 10 层 / 第 2 幕第 26 层 /
   第 3 幕第 41 层，整层宝箱）；Boss 前一层整层篝火；前 5 层不出现精英/篝火
   （第 6 层也不刷精英）；每幕精英 4 个、商店 3 个。**每幕第一个节点是先古事件**：
   先回血（回复缺失生命值的 X%，默认 100），再随机获得一件先古遗物。
   地图按层分行标注层号，**同层房间不相连**；同层房间水平错位、列不严格对齐，
   连线按真实位置以 S 曲线绘制（每条边独立弧度），**线路不交叉/不重叠优先于
   列对齐**；节点不透明，**未到达（蓝灰）/ 已到达（暗色）/ 当前（金色）/
   可到达（蓝色高亮）**用颜色与边框区分，路线藏在节点后面；
   地图提供**图例**（宝箱 / 事件 / 篝火 / 精英 / 商店 / 先古 / 首领），
   图例为**右侧完全固定浮动面板**（在滚动容器外绝对定位，滚动地图时不动），
   悬停图例项时对应类型节点高亮、其余变暗；当前节点出发的可走路线金色高亮；
   Boss 通关进入下一幕，3 幕通关。**每幕 Boss 从专属池随机**
   （第 1 幕：远古守护者/墨影幽灵/仪式兽；第 2 幕：深渊巨龙/知识恶魔/帝皇蟹；
   第 3 幕：女王/实验体）。
4. **构筑系统**：战斗胜利 3 选 1 卡牌奖励（**奖励卡为 3 倍大卡面展示**；**精英额外随机给一件遗物，Boss 胜利也有卡牌奖励**）、商店购买/移除（**移除卡牌按实例用卡图选择，带确认弹窗**）、篝火休息/锻造（**升级卡带确认弹窗**）、随机事件（含触发战斗、花金币选项；**获得遗物有 toast 提示**）。
5. **卡牌实例 ID 架构**（重要）：
   - 游戏外（卡组、数据文件、编辑器）：使用静态卡牌 id，如 strike、heavy_blow
   - 游戏内：战斗开始时每张牌实例化，分配战斗专属 uid（c1、c2...），牌堆/手牌/弃牌堆存 uid，通过 uid→cardId 映射解析
   - 好处：同名牌可区分；战斗中生成的新卡有独立实例；未来可在实例上挂附加效果（遗物/怪物赋予的临时效果）
   - 相关类型：CardInstance（core/types.ts），Combat 内 instances 映射
6. **升级系统**：篝火锻造弹出卡片选择面板，显示「当前卡面 ➜ 升级后卡面」对比；**每次升级只升选中的那一张（按牌组实例），同名多张卡分别展示、互不影响**；事件随机升级也只升一张。升级牌用 `${id}+` 表示，**一律**由基础卡在构建数据库时动态派生（`upgrade` 字段只存覆盖项：费用/描述/效果/消耗），改基础卡数值会自动同步到升级版；编辑器里升级效果支持「继承基础效果 / 自定义升级效果」两种模式切换。**旧格式的显式 `<id>+` 卡数据会在加载时自动清理**，升级卡不允许独立存储。
7. **DIY 编辑器**（主菜单 → 编辑）：
   - 卡牌 / 怪物 / 遗物 / 事件 / **先古**五个页签，可视化表单编辑，行式效果编辑器；
     卡牌与遗物支持**所属角色（无色/通用可选）、拓展包代号（如 STS2）、版本**字段
   - 卡牌效果描述支持「✨ 从效果自动生成」（结构化效果 → 中文文本，可在编辑器一键填充；
     数据库构建时空描述也会自动补全）；卡牌**趣闻**平时不显示在卡面上，
     点开卡片预览弹窗后显示在右侧
   - 「全局设置」页签：初始生命、初始金币、每回合抽牌数、每回合能量、起始牌组、
     **先古回血比例、先古角色、默认角色**
   - 数据分两层（见下），支持导出/导入 JSON；同名 id 覆盖内置数据，值为 null 表示删除内置条目
   - 事件选项支持 goldCost（花金币）、fightEnemy（触发战斗）、addCards、addRelic、
     **addRelicPool（随机遗物池）**、removeCards、loseMaxHp、upgradeRandomCard
8. **UI 布局**：战斗中角色与怪物**水平居中、左右对峙**（角色在左、怪物在右，怪物横向排开），底部手牌、中间日志。地图页有「卡组」「遗物」查看按钮，角色面板与怪物面板位置可用 CSS 变量 `--player-offset-x/y`、`--enemy-offset-x/y` 微调。编辑卡牌时有**基础卡 ➜ 升级卡实时左右对比**。**全部卡牌统一按普通卡方案 A（画窗布局）展示**，支持六种材质（粗布/银灰/合金/金箔/闪卡/玻璃）与跟随鼠标的光影、3D 倾斜；战斗手牌悬停放大 + 弧线。**怪物各有独立两帧待机动画**（史莱姆挤压、蘑菇呼吸、狼摇摆、劫匪弹跳、哥布林念咒、守护者悬浮、巨龙飘游等）。
9. **快捷键**（战斗中）：`A` 抽牌堆、`S` 弃牌堆、`X` 消耗堆、`Z` 移除堆、`D` 牌库（卡组）——按一次打开、再按一次关闭；`F` 任意游戏界面查看地图（可切换开关）；`E` 结束回合；`ESC` 取消卡牌选中；数字 `1-0` 依次选择手牌从左到右第 1-10 张；**空格**打开卡牌预览（悬停/选中卡，按 `Q` 在基础卡与升级卡之间切换）。
   - **防误触出牌**：所有卡牌都采用「先选中、再确认」——单体目标卡选中后点敌人打出；无目标卡（技能/全体/随机）选中后再点一次打出。数字键只负责选中，不会直接出牌。
10. **数据文件夹（data/）**：DIY 正式数据写入 data/*.json（cards/enemies/relics/events/ancients/characters/settings.json），拷走整个项目文件夹即可随身携带。三档数据源自动降级：
   - ① 绑定的 data 文件夹（File System Access API，主菜单或编辑器里点「绑定 data 文件夹」，句柄存 IndexedDB）
   - ② 本地服务器自动读取 `./data/*.json`（npm run dev / 静态托管）
   - ③ localStorage 兜底（file:// 双击打开、未绑定时）
   - 旧的 localStorage DIY 数据（slay-the-spire-diy-v1）会自动迁移到正式层
11. **存档系统**：游戏进程自动存档到 data/save.json（绑定文件夹时）或 localStorage（兜底）；主菜单检测到存档显示「继续上次（第 X 层 · 生命 x/y）」；战斗中不存快照，恢复到战斗前的节点状态；失败/通关自动清除存档。
12. **数值调整分层**：
    - 永久层 = data/*.json（版本/补丁级改动，编辑器「写入正式数据」固化）
    - 临时层 = localStorage 调试覆盖（编辑器「临时微调」，立即生效，可一键「清空临时调整」）
    - 列表条目带来源标记：金色边框 = 正式数据，绿色边框 = 临时调整；删除也分「删除（临时）/删除（正式）」
13. **测试房间**（主菜单 → 🧪 测试房间）：设置初始生命/金币后选择任意事件，立即以该状态进入事件测试选项逻辑；事件结束后自动回到测试房间，方便连续测试。

14. **拓展包体系**：卡牌/遗物/怪物/角色均带 `pack` 字段（当前全部属于 STS2 基础包），
    卡牌/遗物还支持 `character` 归属（留空 = 无色/通用）。未来新增 DLC 时只需
    给数据标新包代号，角色与无色体系已就绪。
15. **STS2 全卡池（EA 0.98.0）**：内置 488 张角色/无色卡，卡名、描述、费用、
    稀有度与升级版均为官方数据；伤害/格挡/抽牌/能量/状态/宝珠/星辰/灵魂/灾厄/
    召唤等可解析效果已精确映射，复杂机制卡（锻造、X 费用、条件增伤等）为近似
    效果并保留原文描述，可在编辑器里精修。数据由
    `scripts/generate_sts2_cards.py` 从官方卡池 JSON 自动生成，更新可重跑。
16. **中文化与悬浮说明**：全部卡名已中文化，效果描述规则化翻译（特殊句逐步精修，
    进度见 `content-roadmap.md`）；状态以图标 + 层数显示，卡牌标签、遗物、
    药水、星辰/灵魂资源、宝珠、召唤物均支持**鼠标悬停浮窗解释**；星辰/灵魂
    消耗显示为卡面徽标。
17. **游戏内弹窗**：所有确认/提示均使用游戏内弹窗（不再弹浏览器 alert/confirm）。

## 战斗事件触发顺序（严格串行，禁止"同时结算"）

游戏里**不存在任何同时发生的事件**：所有看似同时的效果都被拆成固定先后顺序。遗物触发时机可自定义：战斗开始时 / 回合开始时 / 回合结束时 / 打出一张牌时 / 造成伤害时 / 获得格挡时 / 战斗结束时。

1. **战斗开始（combatStart）**：洗牌 → 按获得顺序触发遗物 → 开始第 1 回合
2. **回合开始（turnStart）**：清除格挡 → 重置能量（含遗物加成）→ 中毒结算 → 抽牌（含遗物加成）→ 按获得顺序触发遗物
3. **打出卡牌（cardPlayed）**：支付费用 → 效果数组**逐个按顺序结算**（同一张卡内的多个效果也严格有序）→ 卡牌进弃牌/消耗堆（能力牌进**移除池**）→ 按获得顺序触发遗物 → 战斗结束判定
   - 星辰/灵魂资源卡（储君/亡灵契约师）：打出前先检查 `starsCost` / `soulsCost`，不足不能打出
   - 宝珠（故障机器人）：引导入 3 槽，回合开始按类型触发被动（闪电/冰霜/黑暗/玻璃）；「打出宝珠」效果爆发最左侧宝珠
   - 召唤物（亡灵契约师）：回合开始自动攻击，存活时替玩家挡刀
   - 灾厄：敌人累计 10 层时在其行动前被处决
   - 消耗堆互动：`retrieveFromExhaust` 只取消耗堆，能力牌在移除池不会被打捞
   - 造成伤害：每次命中 = 伤害 → 荆棘反伤 → 触发「造成伤害时」遗物（遗物效果产生的伤害**不会**再次触发，防递归）
   - 获得格挡：计算（敏捷加成/脆弱衰减）→ 获得 → 触发「获得格挡时」遗物（同样防递归）
4. **回合结束（turnEnd）**：弃手牌 → 负面状态衰减 → 按获得顺序触发遗物 → 回合结束状态效果（仪式 → 金属化）
5. **敌人回合**：按入场顺序逐个行动（毒结算 → 行动 → 状态衰减 → 清格挡），玩家死亡立即判负
6. **战斗结束（battleEnd）**：胜利时按获得顺序触发一次，然后结算奖励；失败直接结束

多个遗物在同一时机触发时，一律按**获得顺序**执行。

遗物触发时机新增：**消耗/移除卡牌时（cardExhausted）**（能力牌与带「消耗」标签的牌进堆时触发）、**受到伤害时（receiveDamage）**（玩家实际掉血时触发，遗物产生的伤害不递归）。

## STS2 机制说明

星辰、灵魂、宝珠、召唤、灾厄与药水已按上述规则落地；对应角色卡牌/遗物均标注了
实际效果（见编辑器预览与卡面描述）。药水/遗物/卡牌都带 `pack`（当前全部为 STS2 基础包）。

本轮新增：

- **计数器/延迟效果**：卡牌可设置「下回合 / X 回合后」结算的延迟效果，
  战斗面板显示倒计时徽标（悬停查看内容）
- **锻造 Forge**：升级手牌中的随机实例（储君体系）
- **弃牌与奇巧 Sly**：弃置手牌的效果 + 被弃卡牌的弃牌触发
- **条件增伤**：按消耗堆/易伤/本回合打出的攻击等线性加成伤害
- **风味文案**：稀有卡卡面底部的趣味描述（`flavor` 字段，编辑器可编辑）
- **稀有度材质**：卡牌边框/辉光按稀有度分级（金卡/闪卡 class 预留）

> 约 148 张复杂机制卡为近似效果（描述保留原文，翻译逐步精修），编辑器里可直接精修；
> 完整进度见 `content-roadmap.md`。

## 核心文件

- src/core/types.ts —— 所有数据模型与类型

- src/data/*.ts —— 内置数据（卡牌/怪物/遗物/事件/先古角色）

- src/data/index.ts —— 数据合并（内置 → 正式层 → 临时层）
- src/ui/battleView2.ts —— 战斗界面
- src/ui/ancientView.ts —— 先古事件界面
- src/ui/editorView.ts —— DIY 编辑器（分层保存）
- src/ui/upgradePicker.ts —— 升级卡牌选择面板
- src/ui/testRoomView.ts —— 测试房间（指定事件 + 自定义初始状态）
- scripts/core_test.ts —— 核心逻辑测试（esbuild 打包后 node 运行）
- scripts/generate_sts2_cards.py —— STS2 全卡池生成器（官方 JSON → sts2_cards.ts）
- scripts/copy-data.mjs —— 构建时把 data/ 复制到 dist/data/

## 环境说明

- 环境要求与初始化步骤见 `../GETTING_STARTED.md`（Node >= 18 / 推荐 Chrome/Edge）
- 数据默认存 localStorage（按 localhost 域名）；在编辑器或主菜单绑定 data 文件夹后，正式数据与存档写入 data/ 目录，实现跨电脑随身携带
- 项目级 `.codex/config.toml` 是 Codex 沙箱写权限配置，指向本机路径、不入库；换机器需自行更新
