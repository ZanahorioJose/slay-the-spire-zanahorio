# 动画方案说明：CSS 动画 vs PNG 帧图（Sprite Sheet）

> 适用项目：杀戮尖塔 DIY（Vite + TypeScript + 原生 DOM/CSS）
> 目的：说明两种动画形式的原理、区别、适用场景，以及本项目推荐的使用方式。

---

## 1. 两种方案的原理

### CSS 动画（代码补间动画）

不依赖任何图片素材，用 CSS 关键帧描述"元素怎么动"：

```css
@keyframes idle-float {
  0%, 100% { transform: translateY(0); }
  50%      { transform: translateY(-8px); }
}
```

- 浏览器自动补间（interpolation），无需逐帧画面
- 动的是**整个元素**：位移、缩放、旋转、透明度、抖动
- 典型写法：`transform` / `opacity` 关键帧 + `animation` 属性
- 性能友好：`transform` / `opacity` 走 GPU 合成层，不触发重排

### PNG 帧图（Sprite Sheet）

把多帧画面按网格排进一张大图，代码按顺序切换显示区域：

```text
┌─────┬─────┬─────┬─────┐
│帧 1  │帧 2  │帧 3  │帧 4  │  ← 第 1 行：待机（循环）
├─────┼─────┼─────┼─────┤
│帧 1  │帧 2  │帧 3  │帧 4  │  ← 第 2 行：受击（播一次）
└─────┴─────┴─────┴─────┘
```

- 每一帧都是独立绘制画面，可以表现**角色本体的形变**
- 通过切换 `background-position`（或 `<img>` 帧定位）实现播放
- 控制方式：待机 = 循环播放某一行；受击 = 播放某一行一次后回到待机

---

## 2. 核心区别对比

| 维度 | CSS 动画 | PNG 帧图（Sprite Sheet） |
| --- | --- | --- |
| 素材依赖 | 零素材 | 需要逐帧图片 |
| 表现内容 | 整体位移/缩放/旋转/透明度 | 角色本体动作（形变、挥舞、表情） |
| 动画片感 | "图片在动" | "角色在动" |
| 待机循环 | 简单（浮动/呼吸式整体移动） | 生动（真实呼吸、摇尾巴等） |
| 受击反馈 | 抖动、闪白、缩放 | 后仰、闪红、动作帧 |
| 控制复杂度 | 低（class 切换） | 低-中（切 background-position） |
| 文件体积 | 0 | 随帧数和尺寸增长 |
| 性能 | 好（GPU 合成层） | 好（同一张图，无额外请求） |
| 可扩展性 | 弱（新动作仍只能整体动） | 强（加一行帧 = 加一个动作） |
| 适合表现 | UI 层运动、卡牌飞出、面板震动 | 怪物/人物的本体动画 |

## 3. 使用点（什么时候用哪个）

### 推荐用 CSS 动画的场景

- 卡牌打出时的飞出/缩放/淡出
- 手牌选中上浮、悬停反馈
- 面板/窗口的震动、出现/消失过渡
- 数字跳动、血条变化、状态图标闪烁
- 任何"整体元素运动"且不需要角色形变的反馈

示例（项目已实现）：

```css
@keyframes enemy-idle {
  0%, 100% { transform: translateY(0); }
  50%      { transform: translateY(-6px); }
}
```

### 推荐用 PNG 帧图的场景

- 怪物待机（呼吸、摇摆、飘动）
- 怪物受击（后仰、抖动、闪白）
- 怪物攻击动作（扑击、挥爪、施法）
- 人物/角色动画（挥剑、格挡、施法、死亡）
- 任何"角色本体在动"的内容

---

## 4. 待机 / 受击：推荐 PNG 帧图

前提：素材由 AI 生成，不把制作难度纳入考量。

结论：**待机和受击都用 PNG 帧图**。

理由：

1. 表现力更好——CSS 只能让整张图上下浮动，像贴纸在飘；帧图是角色自己在动。
2. 控制不复杂：
   - 待机 = 循环播放「待机行」的帧
   - 受击 = 播放「受击行」一次，播完自动切回待机
3. 可扩展——以后加攻击、死亡动画，同一套机制加行即可。

---

## 5. AI 出图规范（Sprite Sheet 格式约定）

给 AI 生成帧图时，遵循以下约定，方便代码接入：

1. **透明背景 PNG**
2. **每帧统一尺寸**（如 128×128 或 256×256）
3. **按行分动作**：
   - 第 1 行：待机（4~6 帧，可循环）
   - 第 2 行：受击（3~4 帧，播一次）
   - 第 3 行起：攻击、死亡等（后续扩展）
4. **帧间变化自然**：AI 生成时指定"同一角色、逐帧动作差异"，避免画面跳变
5. 命名建议：`<角色id>_sprite.png`（如 `slime_sprite.png`），与数据文件中的 `art` 字段对应

示例约定：

```text
slime_sprite.png
├── 行 1：待机帧 1-4（循环）
├── 行 2：受击帧 1-4（播一次）
└── 行 3：攻击帧 1-4（预留）
```

---

## 6. 本项目建议的混合使用策略

**PNG 帧图做角色本体动作 + CSS 动画做全局运动**：

| 对象 | 动画形式 |
| --- | --- |
| 怪物待机/受击/攻击 | PNG 帧图 |
| 人物（玩家）动作 | PNG 帧图 |
| 卡牌打出/选中/飞向目标 | CSS 动画 |
| 受击震动、血条变化、UI 反馈 | CSS 动画 |

这样既保证角色表现力，又让 UI 反馈保持轻量高性能。
